# dh-sync: upstream sync job

Daily job that keeps the fork current with OrchestratorInc/agent-orchestrator.

1. Fast-forwards `origin/main` from `upstream/main`. A red day leaves `main` ahead of `dh/main`; the next run recovers.
2. Merges upstream into `dh/main` on a local branch in a sibling worktree (`../agent-orchestrator-sync`).
3. Conflict-free merge with green checks: fast-forwards `origin/dh/main` (exit 0).
4. Conflicts or red checks: escalation (below). A resolved merge never reaches `dh/main` automatically.

It never pushes to `upstream`, never force-pushes, never touches the live checkout, and never resolves a conflict by itself.
If `origin/dh/main` does not exist yet, it only mirrors `main`, logs a warning and notifies (once per day).

## Escalation and safety model

- The resolver is a Claude Code session started in the worktree with an explicit file-tools-only set: `--tools Read,Edit,Write,Grep,Glob` (no Bash at all, so no git and no `git diff --output`), allowed the same, denied `WebFetch,WebSearch,Bash`, `--strict-mcp-config`, `--settings <script-written file>` with `--setting-sources ""` (no settings file is loaded from the worktree, the user or the project; the script-owned settings carry deny rules for `~/.ssh`, `~/.aws`, `~/.config`, `~/.gnupg`, `~/.claude`, `~/.kube`, `~/.docker`, `~/Library`, `/etc` and the live checkout, and `disableAllHooks`; a worktree that contains `.claude/settings.json` or `.claude/settings.local.json` is refused before the resolver starts), `--permission-mode acceptEdits` (edits outside the worktree are not auto-approved and are denied in `-p` mode). No bypass flags. The prompt (`resolve-prompt.md`) is a template with three controlled values (SHA, branch, ticket); upstream commit messages and file contents are never put in it. UNVERIFIED offline (confirm with one live run): that `--settings` still applies with an empty `--setting-sources`, that an empty value is accepted, and that `Read(//abs/**)` deny rules also gate Grep and Glob. A rejected flag is not silent (it ends as "claude rejected its arguments"). Residual risk: the session reads untrusted upstream files (prompt injection); containment is the tool restriction, the deny rules, the path-scope check, the secret scan and the fact that a needs-human result is never pushed.
- There is no `--max-turns` (not in `claude --help` 2.1.331); runtime is bounded by the script's timeout wrapper. If claude exits non-zero with usage/unknown-option text, the job reports "claude rejected its arguments" and notifies. The script then verifies: HEAD attached to the sync branch, merge still in progress (resolver did not commit), no conflict markers, **test-weakening guard**, checks green. Then the script runs the path-scope check, config guard and secret scan below, commits and pushes only to `sync/upstream-<UTC yyyymmdd-HHMM>` (explicit `HEAD:refs/heads/<branch>`, verified with ls-remote) and notifies. Exit 10: land that branch with the harness.
- Guard heuristic (compares the staged result with both parents and the merge base, so one-sided upstream or fork changes are legitimate): fails if a test file (`*_test.go`, `*.test.*`, `*.spec.*`) present in both parents is deleted or renamed away, a skip/only/todo marker is added, or an assertion/test-definition line is removed that the other side did not itself remove (fork-side tests included, checked against dh/main as well as upstream). Not covered: conditions like `if got != want {`, early returns, `__tests__` naming, paths with spaces, and a test file that exists on only one side and contains none of the assertion/test-definition patterns (for example table-driven tests using `if got != want`): deleting it is not detected beyond the removed-line comparison.
- Path scope: only conflicted files (for red checks after a clean merge: only files the merge brought in) may be resolver-authored. Any other modified path, or any new untracked file, is needs-human.
- Config guard: if the resolver authored a change (staged content differs from the pre-resolver index and equals neither parent; files git auto-merged cleanly are not flagged) in package.json, package-lock.json, pnpm-lock.yaml, yarn.lock, go.mod, go.sum, .npmrc, go.work, Makefile/Taskfile, vite/vitest/playwright config, .golangci, a workflow, `.claude/`, .mcp.json, CLAUDE.md or AGENTS.md, the checks are NOT run (they would execute it or later sessions would load it).
- Secret scan: before any push, the added lines of the resolver-authored and conflicted paths are scanned with gitleaks (`AO_SYNC_GITLEAKS`: empty = on PATH, `none` = off, else a program path; invoked as `gitleaks stdin --no-banner --redact`, exit 1 = leak, UNVERIFIED offline; any other failure falls back) or, without gitleaks, a regex for common token and key formats. A hit is needs-human.
- Needs-human (path scope, config guard, secret scan): exit 20, result `needs-human`, NOTHING is pushed (origin is public). The worktree and the local `sync/upstream-*` branch are kept and the notification names the worktree path; the next run removes the worktree but not the branch.
- Clean merge with red checks and an unresolved resolver: the committed merge is pushed to its sync branch for inspection; dh/main is untouched.
- Unresolved conflict: nothing is pushed; the conflict diff and SYNC_SUMMARY.md (if any) are kept in the log directory.

## Operation

Exit codes: 0 landed or noop, 10 resolved and pushed to a sync branch (awaiting land), 20 unresolved, 30 precondition failure (lock held, main not fast-forwardable, push rejected, fetch failed).
The lock holds the PID (liveness check), INT/TERM/EXIT clean up the lock, worktree and local branch, timed jobs run in their own process group which is killed on completion, timeout or signal (TERM, then a bounded KILL for grandchildren that ignore it); the timeout watcher is reaped on exit and signals, and only signals a group that is still alive, a leftover `<repo>-sync` worktree from a killed run is removed only if git registers it as a worktree of this repo (otherwise exit 30 and notify), the worktree HEAD must still equal the merge commit before dh/main is pushed, the job refuses to run if origin and upstream URLs match, the resolver is limited to 45 min (`AO_SYNC_RESOLVER_TIMEOUT`, seconds) and the checks to 60 min (`AO_SYNC_CHECKS_TIMEOUT`).

Logs: `~/Library/Logs/ao-sync/sync.log` (one line per run, includes `skipped=<items>` when checks skipped something), `<timestamp>.log` (full output), `<timestamp>-SUMMARY.md`, `<timestamp>-conflict.diff`, `status.log` (every notification). Files older than 30 days are pruned. `--debug` adds DEBUG lines.

Notifications (`notify.sh`): always a line in `status.log` and a macOS notification. Status: `sent`, `sent-no-banner`, `local-only`, `osascript-failed`. A Slack DM through `claude -p --setting-sources user` is best effort and `sent` only when the session prints SLACK_SENT (the model's own confirmation). It cannot use `--strict-mcp-config` because the Slack connector comes from the claude.ai account; its prompt contains only the controlled notification text. A clean landing with skipped checks also notifies (once per day). The Slack tool name is `AO_SYNC_SLACK_TOOL` (default `mcp__claude_ai_Slack__slack_send_message`, unverified). Lock-held and missing-dh/main notifications are limited to once per day.

Options: `sync.sh [--repo PATH] [--checks PROGRAM] [--resolver PROGRAM] [--notify PROGRAM] [--dry-run] [--debug]` (PROGRAM is a single executable path; paths with spaces are fine).

Checks (`checks.sh`, same commands as CI): gofmt, go build, go vet, `go test -race -count=1 -timeout=10m -json ./...`, golangci-lint (only v2.14.0, the CI pin; another or missing version is SKIPPED), frontend `npm ci`, `npm run typecheck`, `npm run typecheck:e2e`, `npx vitest run`, and the sqlc and API codegen drift checks (generated files are restored afterwards; a generator that cannot run is SKIPPED, never a pass). A skipped item makes the result "green with skips", never plain green.

Known-red baseline: `known-red.txt` lists failures that already exist on dh/main (missing CLIs, timeouts, unresolved modules). Go, vitest and typecheck failures are normalised to `kind|scope|name` lines by `known-red.sh`; only failures NOT in the list make `checks.sh` exit 1 (`CHECKS_KNOWN_RED=<n>` counts the listed ones). A run that fails only on known-red items is a green checks run, so it lands without the resolver. A non-zero exit with nothing parsable is reported as `_run`, never green. Entries ending in `|*` are package/file-level seeds (the current file is seeded from the 2026-11-25 baseline: 12 Go packages, 8 vitest files, the typecheck errors at test level); narrow them with `scripts/dh-sync/regen-known-red.sh` (runs the full suites, 20+ minutes, from a clean dh/main checkout with `npm ci` done; keeps existing package-level entries, writes test-level ones) and review the diff before committing. The log keeps the last 2000 lines of check output; the full output is saved as `<timestamp>-checks-full.log` only when the checks fail. Slack notification text is sanitised before it reaches the Claude prompt and that session is denied file and shell tools (flag form UNVERIFIED offline).

Install: `scripts/dh-sync/install.sh` (copies the scripts to `~/Library/Application Support/ao-sync`, installs the LaunchAgent, daily 07:00). Remove: `scripts/dh-sync/install.sh --uninstall`.

Tests: `scripts/dh-sync/test/sync_test.sh` (temporary bare repos, fake claude/osascript on PATH, no network).
